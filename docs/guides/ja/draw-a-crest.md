紋帳に載っている家紋は<!-- count:book-names -->2,660<!-- /count -->あり、Kamon Crestsが描いたのはまだその一部です（数は[収録状況のページ](https://johnmorrisdotca.github.io/kamon-crests/coverage/)にあります）。残りは描き手を待っています。描いてみたい方のために、このページでは描き方、私たちが求めること、送ったあとの流れを説明します。

プログラマーでなくても始められます。多くの人はAIのコーディングエージェントと一緒に作業しており、このページにはそのためのプロンプトもあります。必要なのは細部への根気です。家紋は1892年刊の紋帳と線ごとに照らし合わせて確かめ、家紋に詳しい人が見ても紋帳の家紋と見分けがつかないものだけを取り込みます。

## 手順の要約

1. Issueを一つ引き受けます。ラベル **draw a crest** の付いた[未解決のIssue](https://github.com/johnmorrisdotca/kamon-crests/issues?q=is%3Aopen+label%3A%22draw+a+crest%22)が描き手を待っている家紋で、**good first issue** も付いたものはやさしい家紋です。「I'll take this」（引き受けます）とコメントすると、メンテナーが担当者に割り当てます。Issueのない家紋は、**Draw a crest** のフォームで新しく立ててください（[どこから始めるか](#どこから始めるかまずはやさしい家紋から)を参照）。
2. やめるときはIssueにそう書いて、ほかの人が引き受けられるようにしてください。2週間連絡のないIssueは、誰でも引き受けられる状態に戻します。
3. 著作権の切れた1892年の紋帳でその家紋を探します（[紋帳](#紋帳形の出どころはここだけ)を参照）。
4. [作図の規則](../../construction-rules.md)に沿って、`scripts/crests/` にコンパスと定規の作図として組み立てます。
5. 比較シート（自分の家紋、紋帳の家紋、紋帳に重ねた自分の家紋）を作り、すべての線を目で確かめます。
6. `pnpm check` を実行します。通らなければなりません。
7. シートを添えてプルリクエストを出します。

## 厳しく守る決まり

これは提案ではありません。一つでも破ったプルリクエストは、絵がどれほど良くても閉じるか差し戻します。

### 形は著作権の切れた紋帳からだけ取る

このパッケージはMITライセンスです。中身はすべて、そのライセンスで配布できるものでなければなりません。

- **形の出どころは1892年の紋帳だけです。** 『伊呂波分新撰紋帳』（1892年）は国立国会図書館が[NDL 780550](https://dl.ndl.go.jp/pid/780550)として公開しており、保護期間満了と記されています。その家紋の枠を測り、自分で引いた円と線から組み立てます。
- **ウィキペディアとウィキメディア・コモンズは確かめるためのもので、写すためのものではありません。** そこにある家紋の絵の多くはCC BY-SA（継承）で、MITのパッケージには入れられません。自分の家紋が同じに見えるかを確かめるために見ることはでき、全体の数をいくつか取ることもできます（花びらの数、全体の縦横比、主な角度）。そこから部分の位置を決めること、その輪郭に重なるまで自分の絵を調整すること、当てはめや探索のスクリプトを実行すること、なぞることは認めません。
- **現代の紋帳、ウェブサイト、フォント、素材集、ソフトウェアは、どれも出どころにしないでください。** それぞれの絵は作った人のものです。どれほど網羅的に見える家紋サイトでも同じです。
- **紋帳に載っていなければ描きません。** 1892年の紋帳にない家紋なら、別の家紋を選んでください。
- **すべての数値に出どころを書きます。** 家紋の `source` と作図の説明に、紋帳のコマ、ページ、段、列と、コモンズの絵から取った全体の数があればそれを書きます。

ここまで厳しいのは、なぞった家紋が一つでもあると、このパッケージを使う全員がライセンスを変えなければならなくなるかもしれないからです。疑わしい家紋が何千あるより、出どころの確かな家紋が数百あるほうを選びます。

### 自分の名前で出し、AIの名前は出さない

- **自分の名前とメールアドレスでコミットしてください。** どう作ったかにかかわらず、作者は自分自身であり、すべての行に責任を負います。
- **AIの名前はどこにも出さないでください。** モデルやツールを共著者として記すトレーラー、ツールが作ったと書く行、ツールやモデルの名前は、コミットメッセージ、コード、コメント、文書、プルリクエストのどれにも入れません。多くのAIコーディングツールはこうした行を初期設定で付けるので、設定で切るか、プッシュする前に消してください。下のプロンプトでもエージェントにそう伝えています。
- **役に立つ道具は、AIも含めて何を使っても構いません。** 見るのは絵とコードで、作り方ではありません。

### 作図の規則

[docs/construction-rules.md](../../construction-rules.md) には家紋を描くすべての規則があり、それぞれにその規則を守らせるテストか、比較シートで確かめるという注記が付いています。始める前に全部を読み、エージェントにも読ませてください。主なものは次のとおりです。

- 家紋は、格子点に中心を置いた整数の幅の円（または、すでに引いた円に接するように置いた円）と、定規で引いた直線でできています。`scripts/construct/compass.ts` で切り、つなぎます。ベジェ曲線も線（ストローク）も使いません。
- 白い線は二つの塗りのあいだのすき間で、上から重ねて描くものではありません。
- まず補助線を引き、次に墨を入れる順に形を描きます。アニメーションはこの順に作られるからです。
- すべてを200×200の紙の中に収め、線の太さはパッケージで決めた太さ（`scripts/construct/builder.ts`）を使います。
- 名前と説明はすべて英語と日本語で書き、読みはひらがなで添えます。英語か日本語のどちらかが書けなければ、プルリクエストにそう書いてください。こちらで書きます。

## どこから始めるか：まずはやさしい家紋から

最初の家紋はやさしいものにしてください。幾何学的な家紋と、すでに描いた紋様を別の囲みに入れた家紋がいちばんの入り口です。道具の使い方が身につき、紋帳の枠も測りやすいからです。

**最初に向いている家紋**

- **すでに描いた紋様を丸などの囲みに入れたもの。** たとえば丸に一つ巴、丸に三つ菱。紋様の組み立てはもうあるので、パッケージの丸の中に置くだけです。`maru-ni-kaji-no-ha` の作り方を見てください。
- **菱**：三つ菱、二階菱、五階菱、違い菱。
- **隅切り角**：<!-- count:corner-squares-ja -->20の家紋のうち、0が描かれています。<!-- /count -->
- **目結**：隅立て四つ目（六角家の家紋）、三つ目。
- **亀甲**：一重亀甲、次に六角形の中に紋様を入れたもの。
- **筋違**と**一文字**。

**あとに回すもの**

- 葉脈、羽、花びらの多い植物や動物（菊、鶴、蝶、藤）。慎重な測定と確認がたくさん必要です。
- 文字紋。字形をフォントから取ってはいけないので、手本になる筆書きの字が紋帳にあることが必要で、しかも円と線で組み立てるのが難しいからです。

[収録状況のページ](https://johnmorrisdotca.github.io/kamon-crests/coverage/)と[docs/coverage.md](../../coverage.md)には、描いたものも描いていないものも、すべての家紋が章と系統ごとに並んでいます。ティア1は系統の基本形と有名な家紋、ティア2はよく見る変わり紋、ティア3はより珍しいものです。

**ほかの人が描いていないか確かめます。** 家紋はIssueを通して引き受け、自分に割り当ててもらいます。Issueのない家紋は、まず未解決のIssueとプルリクエストを名前で検索し、それから立ててください。メンテナーも系統をまるごと描くことがあります。ピン留めされたIssue **Families being drawn now**（いま描いている系統）に載っている系統は避けてください。

## 紋帳：形の出どころはここだけ

1. [NDL 780550](https://dl.ndl.go.jp/pid/780550)を開きます。1コマは見開き2ページを撮影した1枚の画像で、ビューアーのアドレスの末尾がコマ番号です（`https://dl.ndl.go.jp/pid/780550/1/36` は36コマ目）。
2. この紋帳はいろは順に並んでいます。家紋を探すには、同じ系統の家紋が紋帳のどのコマを出典にしているかを見ます。`docs/provenance.md` を系統名（たとえば巴や菱）で検索すると、近いコマが分かります。変わり紋は前後のコマにあります。
3. 枠の場所を書き留めます：コマ、左か右のページ、段、列。`docs/provenance.md` のどの家紋もこの形で枠を示しています。
4. ビューアーからコマをダウンロードし、枠を切り抜きます。**自分で使うためだけです。** コマの画像も切り抜きもリポジトリには入れません。
5. 測ります：家紋の幅、円の中心と半径、まっすぐな辺の角度。それをパッケージの200単位の紙の上での単純な数値に直し、そこから組み立てます。

紋帳は手描きの輪郭線で、数度傾いていることもあります。図案が明らかに正確さや左右対称を意図している部分は、正確かつ左右対称に描き、紋帳と違う点とその理由を作図の説明に書いてください。

## 準備

Node 24以降、pnpm、gitが要ります。

```sh
# GitHubで johnmorrisdotca/kamon-crests をフォークしてから:
git clone https://github.com/<you>/kamon-crests.git
cd kamon-crests
pnpm install
pnpm exec playwright install chromium   # 一度だけ：絵、プレビュー、デモのテストが使うブラウザー
git checkout -b draw/<crest-id>        # 家紋一つ、または少しのまとまりごとに一つのブランチ
pnpm check                              # 何か変える前に通ることを確かめる
```

使うコマンド（どれも [CONTRIBUTING.md](../../../CONTRIBUTING.md) にあります）：

```sh
pnpm data       # scripts/crests から生成ファイルを作り直す（家紋を変えるたびに実行）
pnpm pictures   # READMEの絵を撮り直す（絵を変えるたびに実行し、結果をコミット）
pnpm coverage   # docs/coverage.md（描いた家紋とまだ描いていない家紋の一覧）を書き直す（結果をコミット）
pnpm dev        # http://127.0.0.1:8850 でデモを開き、家紋が描かれていく様子を見る
node scripts/preview.ts out.png 8852 <crest-id> --size 300 --guides   # 家紋と補助線の絵
pnpm check      # 関門：リント、型、ビルド、文書、テスト、サイズ、パッケージ
```

`src/crests/`、`src/steps/`、`src/data/` の中、`docs/catalogue.md`、`docs/sizes.md`、`docs/strings-ja.md`、`docs/provenance.md`、`docs/coverage.md` は手で編集しないでください。最後の一つは `pnpm coverage` が、ほかはすべて `pnpm data` が生成します。

## 比較シート

家紋ごとに一枚作り、どのプルリクエストにも添えます。家紋が正しいことを、自分もエージェントもレビューする人も、これで確かめます。

家紋一つにつき一行で、絵はすべて同じ大きさ、同じ色にし、次の順に並べます。

1. **自分の家紋**：仕上がったもの、白地に黒。
2. **紋帳の枠**：切り抜いて同じ大きさにしたもの。
3. **紋帳の枠に重ねた自分の家紋**：赤で、半透明に。
4. **コモンズの絵**：あれば、確かめるためだけに。
5. **補助線つきの自分の家紋**：`node scripts/preview.ts … --guides` で作ったもの。

各行の下に一行、紋帳と違うところとその理由を書きます。

そのうえで、エージェント任せにせず、すべての行を自分の目で見てください。家紋に詳しい人がひと目で紋帳の家紋だと思い、コモンズに同じ家紋があるならそれとも同じに見えるときだけ合格です。基準になるのは「テストが通ったこと」ではなく、絵です。

## AIエージェントを使う

多くの人がコーディングエージェントを使っており、歓迎します。強いものを、推論を上げて使ってください。家紋は幾何学的な小さな判断の積み重ねで、弱いエージェントや急いで済ませようとするエージェントは、テストは通るのに見た目が紋帳と違う家紋を作ります。

- **エージェントで使える最も強いモデルを**、推論の強さを **high** か **very high** にして使います。ごく簡単な幾何学的な家紋なら中位のモデルでも描けますが、植物、動物、白い線の多いものには最も強いモデルが要ります。
- **シートは自分で見てください。** エージェントは、見れば明らかに違う家紋にも自信を持ちがちです。
- ピン留めされたIssue **[Using an AI agent](https://github.com/johnmorrisdotca/kamon-crests/issues?q=is%3Aissue+in%3Atitle+%22Using+an+AI+agent%22)**（AIエージェントの使い方）に、うまくいったモデルと設定、各ツールが自動で付ける作成者表示の行を切る方法を書いています。

### 決まりはリポジトリがエージェントに伝えます

決まりを貼り付ける必要はありません。

- リポジトリのルートにある **`AGENTS.md`** は、多くのコーディングエージェントが作業の前に読みます。出どころの決まり、シートの決まり、AIの名前を出さない決まりが書いてあり、このページを指しています。
- リポジトリには、対応するエージェント向けに次のものも入っています。特定のツールが付ける共著者の行と「作った」行を切るプロジェクト設定、このページの手順に沿った **draw a crest** と **review a crest** の二つのスキル、新しい文脈で動く厳格な **crest reviewer** です。それぞれの場所と使い方はピン留めのIssueに書いています。

下のプロンプトはどのエージェントにも使え、手順を自分で進めたいときにも使えます。日本語のままでも、英語版のページのものでも構いません。

### プロンプト2：厳しく確かめる

組み立てた会話とは別の、新しいセッションで実行してください。

```text
このリポジトリの家紋 <crest-id> を、悪いところを見つけることが仕事の厳しいレビュアーとして確かめてください。
先に docs/construction-rules.md と docs/guides/ja/draw-a-crest.md を読んでください。

1. <path> の比較シートを開き、この家紋を1892年の紋帳の枠と一行ずつ比べてください：すべての円、
   すべての辺、すべての白い線、全体の大きさと位置、線の太さ。どんなに小さくても違いをすべて挙げ、
   それぞれについて、作図の説明に理由が書かれているかも答えてください。
2. 家紋に詳しい人が、ひと目でこれを紋帳の家紋だと思うでしょうか。思わないなら、なぜですか。
3. docs/construction-rules.md の規則を一つずつ、この家紋の組み立てに当てはめて確かめ、破っている規則を挙げてください。
4. ライセンス：紋帳の枠以外から来た形、位置、数はありますか（作図の説明に明記された、
   コモンズから取った全体の数がいくつかある場合は除きます）。組み立ての中に、当てはめの跡がないか
   探してください：小数の桁が多い、少しずつずらした数、絵と比べるスクリプト。
5. 言葉：日本語名は正しいか、読みは正しいか、作図の説明は組み立てのとおりか。
6. `pnpm check` と `pnpm test:demo` を実行して結果を報告してください。
7. コミット：どれも人が作者になっていて、モデルやツールを共著者とするトレーラー、
   ツールが作ったと書く行、ツールやモデルの名前がどこにもないか。

判定（合格、または要修正）と、番号付きの修正一覧を出してください。自分では何も直さないでください。
```

## プルリクエストを出す

- **プルリクエスト一つに家紋一つ**、または同じ系統の少数のまとまり（五つくらいまで）にしてください。
- 先に最新の `main` にリベースします。ほかの人も家紋を足しているので、リベースのあとにもう一度 `pnpm data` を実行し（家紋に順に番号を振ります）、変わったファイルをコミットしてください。
- `pnpm check` は、READMEの数もデータと照らし合わせます。「What's in it」の表の数と、「N crests」という家紋の総数です。家紋を足すと数が変わるので、これで失敗したら、指摘された数を直し、READMEがほかの場所で家紋の総数を書いているところも直してください。
- 新しい家紋のコミットは `feat: <日本語名> (<id>), <何であるかを短く英語で>` の形にします。書き方は `git log` を見てください。
- 家紋ごとに `CHANGELOG.md` の **Unreleased** の下に、そこにある書き方で一行足します。
- その行の終わりに *Contributed by [@you](https://github.com/you).* と書いてください。この行はリリースノートにそのまま載るので、リリースのたびに、家紋を描いた人への感謝が記されます。
- **[scripts/contributors.mjs](../../../scripts/contributors.mjs) に自分の名前を加えてください。** 名前、GitHubのユーザー名、家紋のIDを書き（すでに載っている場合は、自分の行にIDを足します）、`pnpm contributors` を実行します。これでREADMEの **People who helped**（協力してくれた人たち）に名前が載り、デモサイトの家紋のカードには「制作：」に続けて名前が表示されます。
- プルリクエストのテンプレートを埋め、**シートを添えてください**（PNGを説明欄にドラッグします）。

## 送ったあとの流れ

- **メンテナーはまずシートを見て、それから組み立てを見ます。** 最初の家紋はたいてい一、二度、短い修正一覧とともに戻ってきます：少しずれた円、細すぎる白い線、パッケージで決めた太さと違う線、日本語の読みの抜け。よくあることで、家紋の仕上がりをそろえておくための手順です。
- **取り込むとき家紋の番号が変わることがあります。** ほかの人の家紋が先に入った場合です。想定内のことで、`pnpm data` が処理します。
- **取り込まれた家紋は、次の `@johnmorrisdotca/kamon-crests` のnpmリリースに入り**、[デモサイト](https://johnmorrisdotca.github.io/kamon-crests/)で一歩ずつ描かれていきます。コミットには作者として自分の名前が残り、家紋のカード（「制作」）、READMEの **People who helped**、リリースノートにも名前が載ります。
- **貢献した内容はMITライセンスになります。** パッケージのほかの部分と同じです。
- **紋帳以外から形を取ったプルリクエスト、紋帳の枠と照らし合わせられないプルリクエストは閉じることがあります。** 気を悪くしないでください。パッケージを使う全員のために、ライセンス上の問題のない状態を保つ必要があります。

## 質問

Issueを立てるか、プルリクエストの中で聞いてください。形でつまずいたら、そこまでのものをプッシュし、プルリクエストを下書きとして出して、どこで困っているかを書いてください。はっきりした質問の付いた描きかけの家紋のほうが、間違った作り方で仕上がった家紋より手助けしやすいのです。
